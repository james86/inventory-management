Factory Inventory Management System

Full-stack demo for a Claude Code workshop: inventory tracking, order management, demand forecasting, and spending analytics for factory operations. A Vue 3 single-page app talks to a FastAPI backend serving in-memory mock data.

Vue 3 + Vite · :3000 FastAPI · :8001 In-memory JSON (no DB) Demo only

System Architecture

Three tiers. The Vue client renders views and holds filter state; api.js turns filters into query params over HTTP. FastAPI validates with Pydantic, applies the filters in-memory, and returns JSON loaded from static files at startup. No database — data lives in process memory.

Data Flow

The path a single filtered request takes, end to end. Matches the pattern documented in CLAUDE.md: Vue filters → api.js → FastAPI → in-memory filtering → Pydantic validation → computed properties.

1

User sets a filter

FilterBar updates shared state in the useFilters composable (Time Period, Warehouse, Category, Order Status).

2

Client builds the request

api.js drops 'all' values and serializes the rest into URLSearchParams, then issues an axios GET.

3

FastAPI receives & routes

Endpoint reads optional query params. CORS allows the cross-port (3000→8001) request.

4

In-memory filtering

apply_filters matches warehouse/category/status; filter_by_month resolves a month or quarter against order_date.

5

Pydantic validation

Result is validated against the response model (e.g. List[Order]) before serialization to JSON.

6

Client stores raw data

Response lands in refs (allOrders, inventoryItems). Derived metrics live in computed properties.

7

Reactive render

Views and SVG charts re-render from computed values. Detail modals fetch single items on demand.
